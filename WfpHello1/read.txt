ALE 重定向 + “影子路由”
这是最稳妥的办法。你不需要完全删除所有路由，而是给虚拟网卡（vNIC）配置一个极低优先级（高 Metric）的默认路由。

影子路由： 给 vNIC 增加一个 0.0.0.0/0 路由，Metric 设为 9999。这确保了 Socket 层认为“有路可走”，不会直接报错。

WFP 拦截： 在 FWPM_LAYER_ALE_CONNECT_REDIRECT_V4 层拦截流量。

强制绑定： 将 localAddressAndPort 修改为 vNIC 的 IP（10.8.0.4）。

结果： 由于源 IP 被强行绑定到了 vNIC，根据 Windows 的 Strong Host Model，协议栈会强制让报文从该 IP 所在的网卡（即 vNIC）发出。


route add 0.0.0.0 mask 0.0.0.0 10.8.0.4 metric 9999


# 开始重定向（把 PID 1234 的所有流量重定向到 10.8.0.2）
wfpredir_ctrl set 1234 10.8.0.2

# 停止重定向
wfpredir_ctrl clear


# 1. 安装驱动（管理员）
sc create WfpRedirect type= kernel binPath= "C:\path\to\WfpRedirect.sys"
sc start WfpRedirect

# 2. 查到目标进程的 PID（比如 chrome.exe）
tasklist | findstr chrome

# 3. 开始重定向
wfpredir_ctrl set <PID> 10.8.0.2

# 4. 打开 DebugView 看日志，会输出每条被重定向的连接

# 5. 停止
wfpredir_ctrl clear
sc stop WfpRedirect
